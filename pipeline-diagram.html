Interview points

Say this first

What did you build?
GitHub repo → Azure Pipeline YAML → Maven quality gate → JAR to Dev App Service → manual approve → Prod. Image also pushed to ACR. Secrets from Key Vault. Infra as Bicep. App Insights for monitoring.

CI / CD

CI vs CD?
CI = every PR/main build: compile, test, package. CD = after tests pass on main: infra + Dev + approval + Prod.
Why YAML, not classic UI?
Pipeline lives in Git with the app. Same review as code. Repeatable.
PR vs main?
PR: Maven verify only — no Azure change. main: build + ACR + Bicep + Dev + Prod.
Quality gate?
mvn clean verify with fail-if-no-tests. Red tests stop the pipeline. No JAR, no deploy.

Artifacts and deploy

What is the deploy artifact?
The Spring Boot JAR (drop artifact). App Service Linux, Java 21, az webapp deploy --type jar.
Why ACR if App Service is not Docker?
F1 Free cannot run custom containers. ACR stores the image for local Docker / later SKUs. Live site is still the JAR.
Dev then Prod?
Same JAR. Deploy Dev first. Azure DevOps production environment requires approval. Same idea as ML: test endpoint, then prod API.

Azure pieces

Bicep?
Infrastructure as code: App Service plan, Dev/Prod apps, App Insights. Pipeline creates/updates resources instead of clicking the portal.
Key Vault?
Greeting is not in Git. App setting APP_GREETING is a Key Vault reference. App identity reads the secret.
App Insights?
Connection string on the web app + Java attach. Requests and failures in one place.
How does the pipeline talk to Azure?
Service connection with workload identity (no password in YAML). Resource-group scoped.

They may ask next

F1 502 / deploy timeout?
Free plan: one small worker, no Always On. Running Java fights Kudu. Fix: stop → deploy JAR → start, and do not wait for F1 “site started.”
Two apps one plan?
Dev and Prod share F1 memory. Fine for a lab; in real prod use separate plans or a paid SKU.
How would you do this for an ML model?
Same flow. Artifact is a model image/version. Serve as an HTTP API. Dev endpoint → approve → prod endpoint.

Local Docker (localhost:8080) is separate — compose image or docker pull from ACR.
